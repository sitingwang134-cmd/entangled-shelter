## Visual comparison interpretation

The earlier art-rich captures in the page reference folder show the complete Renaissance background, both figures, product props, central frame, typography, and responsive cropping. The earlier `VISUAL_QA.md` records the 1440 × 900 and 390 × 844 first viewports as 100% identical against those source captures. The saved 768 px reference was captured at a different stateful header phase, so it was not treated as a strict same-frame assertion.

The latest forced-WebGL audit deliberately exercised both origins again. Its resulting state varied by run:

- desktop: original remained on the black wireframe shell while local completed the art scene;
- tablet: both sides remained on the black wireframe shell;
- mobile: original completed the art scene while local remained on the shell.

Accordingly, the `qa-results.json` pixel percentages from this forced-WebGL pass must not be interpreted as visual regressions. A black-shell 0% diff proves only that both captures were in the same loading state; a roughly 99% diff proves only that one capture completed WebGL initialization before the other. The valid visual evidence is the previously saved art-rich source/local baseline, not this nondeterministic headless timing sample.

## Error and network notes

There were no JavaScript `pageerror` events and no HTTP 4xx/5xx responses. A console resource message for Google Tag Manager (`ERR_CONNECTION_CLOSED`) appeared on both the original and local page. Some WebGL model, KTX2 texture, and video requests were reported as `ERR_ABORTED` while the automation rapidly swept the page or closed the browser context; the same class of abort appeared on the source page and did not produce broken `<img>` elements or application exceptions.

## Residual differences and risk

1. The mirror still depends on Shopify CDN/MyShopify assets and source JavaScript. It is locally served, but it is not a fully offline/self-contained reconstruction. Network loss or upstream asset changes can affect WebGL/video rendering.
2. Headless WebGL startup is nondeterministic without an application-level scene-ready signal. Automated visual regression should wait for an art-scene readiness condition or use the saved art-rich baseline/fallback poster before comparing pixels.
3. This audit covered first viewport, responsive geometry, a full lazy-load scroll sweep, bottom reachability, title/content, image integrity, console/page errors, and responsive menu toggling. It did not submit search, signup, or third-party outbound flows.
